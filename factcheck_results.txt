ISSUES: IntFloatUnion
*   The `IntFloatUnion(int value)` constructor includes `this.FloatValue = 0; // zero the other field`. When using `StructLayout(LayoutKind.Explicit)` for overlapping fields like `IntValue` and `FloatValue` at the same memory offset, assigning `IntValue` directly overwrites the entire 4 bytes. The preceding assignment `this.FloatValue = 0;` is redundant and the comment is misleading, as it does not "zero the other field" as a separate, necessary step for the union's integrity; it merely writes zeros to the memory that will be immediately overwritten by `IntValue`.
*   The `IntFloatUnion(float value)` constructor is incomplete, lacking its implementation body.
*   The comment `// Increment mantissa → next representable float` for `u.IntValue += 1;` is an oversimplification. While `u.IntValue += 1` is a common technique to get the next representable float for many positive normal numbers, it does not *always* equate to solely "incrementing the mantissa." Incrementing the raw integer bits can affect exponent and sign bits, especially near boundaries (e.g., subnormal numbers, very large numbers, or negative numbers), leading to complex behavior not strictly described as a simple mantissa increment.
